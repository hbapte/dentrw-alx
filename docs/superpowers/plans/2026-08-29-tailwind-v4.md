# Tailwind v4 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `tailwindcss` from v3.3 to v4 using the `@tailwindcss/vite` plugin, drop the dead `tailwind.config.js` / PostCSS pipeline, and confirm no visual regressions.

**Architecture:** Run the official `@tailwindcss/upgrade` codemod for the mechanical parts (directive rewrite, deprecated-class renames, compat layer), then reconcile to the Vite-plugin setup with no JS config file.

**Tech Stack:** Vite 8, `@vitejs/plugin-react` 6, `tailwindcss` 4, `@tailwindcss/vite` 4, bun 1.4, Vitest 4. Design: `docs/superpowers/specs/2026-08-29-tailwind-v4-design.md`.

## Task 2: Switch to the Vite plugin, drop the dead config

**Files:**

- Modify: `package.json`, `vite.config.mjs`, `src/index.css`, `.prettierrc`
- Delete: `postcss.config.js`, `tailwind.config.js`

- [ ] **Step 1: Install the Vite plugin, remove the PostCSS deps**

```bash
bun add -d @tailwindcss/vite@4
bun remove autoprefixer postcss @tailwindcss/forms
bun remove @tailwindcss/postcss 2>/dev/null || true   # only if the codemod added it
```

- [ ] **Step 2: Wire the plugin into `vite.config.mjs`**

Add the import alongside the others:

```js
import tailwindcss from "@tailwindcss/vite"
```

Add `tailwindcss()` to the `plugins` array, right after `react()`:

```js
  plugins: [
    react(),
    tailwindcss(),
    apiDevPlugin(),
    VitePWA({
```

- [ ] **Step 3: Delete the config files**

```bash
git rm postcss.config.js tailwind.config.js
```

If `src/index.css` contains a `@config "../tailwind.config.js";` line the codemod added,
delete that line.

- [ ] **Step 4: Finalize `src/index.css`**

It must start with `@import "tailwindcss";`. Keep any codemod compat `@layer` block. Ensure
the announcement variable + keyframe are present, and add the button-cursor base rule. The
non-Tailwind portion should read:

```css
:root {
  --announcement-height: 0px;
}

@keyframes announcement-slide-down {
  from {
    transform: translateY(-100%);
  }
  to {
    transform: translateY(0);
  }
}

/* v4 makes <button> default to `cursor: default`; keep the pointer. */
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```

- [ ] **Step 5: `.prettierrc` — point the Tailwind plugin at the stylesheet**

Add this key to `.prettierrc` (top level, next to `"plugins"`):

```json
  "tailwindStylesheet": "./src/index.css",
```

- [ ] **Step 6: Update `browserslist` in `package.json`**

Replace the `browserslist` object with:

```json
  "browserslist": [
    "last 2 versions",
    "not dead",
    "fully supports es6-module"
  ],
```

- [ ] **Step 7: Clean install + build**

```bash
bun install
bun run build
```

Expected: build PASSES. Look at the emitted `dist/assets/*.css` — it should exist and be a
sane size (tens of KB). If the build errors on the Tailwind plugin, check the plugin order in
`vite.config.mjs` and that `@import "tailwindcss";` is the first line of `src/index.css`.

- [ ] **Step 8: Commit**

```bash
git add -A
git commit -m "build: use @tailwindcss/vite, drop postcss config and dead tailwind config"
```

## Self-review notes

- The codemod output in Task 1 is committed **before** the Vite-plugin switch so the two
  concerns stay reviewable in isolation and either can be reverted independently.
- `@tailwindcss/forms` removal is safe: `tailwind.config.js` `plugins: []` never loaded it,
  so form controls render with browser defaults today and will continue to.
- No CI file changes: CI runs `bun install --frozen-lockfile` then the gates; the lockfile is
  committed with the dep changes.
- If `bun run dev` / `bun run build` fail specifically because `@tailwindcss/vite` rejects
  Vite 8 at runtime (despite the peer range), the fallback is `@tailwindcss/postcss` in a
  minimal `postcss.config.js` — note this in the PR and keep `postcss` as a dep in that case.

## As-built notes

- **CSS bundle**: 35.7 kB → 49.9 kB raw (8.9 → 11.3 kB gzip). Expected v4 growth (more CSS
  variables, `@property` rules, larger preflight). Still small.
- **Codemod extras handled in Task 2**: it wired the unused `primary` palette into
  `@theme` and rewrote one `text-[#3b82f6]` → `text-primary-500`. Per the "no custom
  palette" decision, the `@theme` block was deleted and that class reverted to
  `text-blue-500` (`#3b82f6` is exactly `blue-500`).
- **Codemod class rewrites kept as-is** (all visually equivalent): `bg-gradient-to-r`→
  `bg-linear-to-r`, `top-[var(--announcement-height)]`→`top-(--announcement-height)`,
  `max-w-screen-{lg,xl}`→`max-w-(--breakpoint-{lg,xl})`, `max-w-[40rem]`→`max-w-160`,
  `rounded`→`rounded-sm`, `rounded-sm`→`rounded-xs`, `shadow-sm`→`shadow-xs`,
  `outline-none`→`outline-hidden`, `opacity-[100%]`→`opacity-100`, `-mx-0`→`mx-0`.
- **`tailwind.config.js` was deleted by the codemod itself** (Task 1), not Task 2.
- **`vite.config.mjs` `test.css`** set to `false` — the v4 Vite plugin made per-run CSS
  processing expensive; tests assert DOM/text only.
- **Visual regression pass (Task 4)**: compared computed styles before/after —
  `border-color` stays gray-200 (v4 `oklch` notation, same colour, via the codemod's compat
  `@layer`); `shadow-xs`/`shadow-md`/`shadow-lg` byte-identical; gradient renders
  blue-600→blue-700; `text-blue-500` correct; announcement-bar `--announcement-height`

- **Browser automation was flaky** this session (frozen renderer, screenshot errors); the
  verification leaned on computed-style measurement + the production CSS output + one clean
  screenshot rather than a full before/after image matrix. Recommend a look at the Vercel
  preview at mobile width.

## Post-review fix: v4-activated dead spacing classes

The visual pass (Task 4) checked hero/contact/footer but missed Services/Insurance/Team. v4's
**dynamic spacing scale** turns any `{h,w,gap,…}-<n>` into `n × 0.25rem`, so classes that were
silent no-ops under v3 (v3 only has a fixed subset) suddenly take effect:

| file                                 | class            | v3    | v4                                                                                                | fix                                                                                                                               |
| ------------------------------------ | ---------------- | ----- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `Services.jsx` `<ul>`                | `h-30`           | no-op | `height: 120px` → 8-card grid clamped, cards overflowed into Insurance                            | removed `h-30`                                                                                                                    |
| `Insurance.jsx` `.slider` / `.slide` | `h-100`, `w-250` | no-op | 400px / 1000px → abandoned "slider" broke, logos overflowed                                       | rebuilt as a clean responsive logo grid (`LOGOS` array, `grid grid-cols-2 sm:grid-cols-4`, uniform `h-10 sm:h-12 object-contain`) |
| `Team.jsx` `<img>`                   | `h-60`           | no-op | `height: 240px` + the pre-existing `object-cover` → team photos became uniform cropped thumbnails | removed `h-60` (keeps the v3 natural-height look; uniform thumbnails would be a separate enhancement)                             |

Swept the rest of `src/` for numeric spacing/opacity/leading/gap classes outside v3's scale —
these three were the only ones. Fixed in commit `fix: dead spacing classes that Tailwind v4 activated`.

## Context (why these plans exist)

DentRW is a React marketing site for a dental clinic (ALX SE frontend final
project). An audit found that **CI has been failing on every push** (invalid
workflow), **the test suite is dead** (wrong runner in CI, the one test asserts
text that isn't in the app), and the repo's docs/config/CI were **half-migrated
to a Vite + Vitest + TypeScript stack that was never actually built** — the app
still runs on Create React App. These plans repair the baseline, finish the
migration, then build on it (SEO/PWA, i18n).

## Findings considered and rejected / deferred

- **`class=` / `for=` instead of `className` / `htmlFor` across 8 components**
  (Contact, Footer, Hero, Insurance, Services, Sign, Team, Testimonials):
  real inconsistency, React 19 logs console warnings, but zero user-facing
  impact and a large mechanical diff. Deferred — fold into 003's manual smoke
  pass or a standalone lint-rule-flip later (`react/no-unknown-property` is
  currently `off` in `.oxlintrc.json`). Not worth its own plan now.
- **`Testimonials.js` is 821 lines of copy-pasted markup**: worth a data-driven
  refactor (→ ~1/5 the size) but it's isolated, low-risk-to-leave, and churny to
  review. Deferred until after the Vite migration so the refactor lands in the
  new structure.
- **`console.log`/`console.error` in `Footer.js:41,50`**: trivial; sweep it in
  whatever plan next touches `Footer.js` (003 renames its env vars).
- **ConvertKit `api_key` sent from the browser (`Footer.js:35`)**: this is how
  ConvertKit's public v3 form-subscribe endpoint is designed to work — the key
  is not a server secret. Not a vulnerability. (The v3 API being deprecated is a
  separate future concern.)
- **Impossible-looking dependency versions in `package.json`** (`typescript ^6`,
  `@types/node ^26`, `prettier ^3.8.4`): it is 2026-08 and Renovate has been
  bumping aggressively — these resolve via `bun.lock`. Not investigated further.
